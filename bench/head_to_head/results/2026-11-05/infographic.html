fastbrowse vs Browser Use

Six tasks, three repeats each, 2026-11-05. fastbrowse and open-source Browser Use ran on one machine; the Browser Use Cloud arms ran on Browser Use's.

Against Browser Use's own cloud presets, fastbrowse no longer leads overall. On these six tasks bu-ultrafast was faster on four and cheaper on five, but it gave the same wrong answer on all three runs of one short task. fastbrowse kept its lead on the search form and the dynamic page, and failed 2 of 3 on the aggregation task.

Reliability: fastbrowse 16 of 18, open-source Browser Use 18 of 18, Browser Use Cloud default 18 of 18, bu-ultrafast 15 of 18, bu-fast 18 of 18. Median wall clock across all runs: 13.3s, 26.8s, 18.4s, 12.1s, 15.2s. Mean model cost per run: $0.0692, $0.0357, $0.0036, $0.0028, $0.0017.

This is not like for like. The hosted arms ran on Browser Use's machines and browser on GPT-6 Luna, while fastbrowse ran on this machine on Gemini 3.8 Flash, whose rates are several times higher per token. So part of the gap may be the model, and this run cannot say how much. fastbrowse has not been run on GPT-6 Luna here.

How to read these numbers

  • The hosted arms are not on the same machine or the same model. Browser Use's presets exist only on its cloud, so its agent, browser and network are its own, and it runs GPT-6 Luna where the local arms run Gemini 3.8 Flash. The clock runs from the create request to seeing the run finish, polled every 0.25 s, so it includes the round trip and queueing. fastbrowse has not been run on GPT-6 Luna here.
  • Hosted cost is model and search charges, the same kind of figure as the local arms, with the browser bill shown apart. Steps come from the run's event stream, one per model turn, and the final URL is read from the browser over CDP.
  • The hosted arms were run after the local ones, on the same day. The checkout's two public credentials are in their prompt, since the API's secret bindings need a vault.
  • Steps are not the same unit. A Browser Use step is one model turn and can hold several actions. A fastbrowse step is one browser action; its reads and checks are extra model calls. Model calls are the closer measure of work, and they are not equal work either: a Jev call is a small, fast choice.
  • Tokens here are the shared text model only. Jev's far larger, far cheaper token counts are in the table below. Dollars cover everything each arm was charged.
  • The text model is pinned, not fastbrowse's default. Both arms use the same model, so these figures do not describe fastbrowse on its default model.
  • How Browser Use won the aggregation task. It wrote one JavaScript call that fetched and tallied every page. fastbrowse has no such tool and clicked through the pages. In the two failed runs it looped for over 100 steps and its verifier refused the answer: one run returned nothing, the other named two of the three authors and said its evidence was partial.
  • Three repeats show large gaps, not small ones. The machine is shared and the sites and model provider are live, so a task's numbers can move between campaigns.
  • Six practice-site tasks are a small sample. They say little about hard or bot-walled sites.
